# 已知限制

## 1. 检测能力边界

- **只覆盖公开、无需登录的页面**。需要登录、验证码、付费墙或地区定向的内容一律不检查。
- **最多 50 个页面、深度 2**。超出部分在「本次检查限制」中说明，不做采样推断。
- **不检查外部链接**。只检查站内链接，避免扫描范围失控。
- **不渲染交互**。默认只读取 HTML；仅当正文极少时才尝试浏览器渲染（Playwright 未安装则跳过）。
  依赖点击、滚动、懒加载或登录后接口的内容可能读不到。
- **不做 SEO / 性能 / 无障碍 / 安全审计**，也不给法律结论。
- **不检查图片、PDF、视频里的文字**，也不识别截图或图表中的信息。

## 2. 误报与漏报

可能误报（已在规则中降权或标注为「建议检查」）：

- 同一产品在不同国家或渠道的合法差异化定价；
- 限时促销、历史活动页、代理商页面；
- 起步价与固定价混排（已排除「起 / 低至 / from」等语境）；
- 结构性模板文本中出现的数字（例如「支持 10 人以上的团队」）；
- 页面中同时存在新旧两套联系方式（会作为候选提示，不判定谁错）。

可能漏报：

- 用图片或脚本动态写入的价格、日期；
- 语义等价但表述完全不同的冲突（例如「首年 8 折」与「¥2399/年」）；
- 需要跨语言理解的不一致（中英文版本内容不同步）。

## 3. AI 复核

- AI 只处理规则已发现的候选，不读取整站自由发挥，也不联网搜索。
- 未配置 `AI_API_KEY` 或服务超时 / 返回不可解析时，自动降级：依赖 AI 的低置信度候选（功能状态、额度）
  直接丢弃，价格与试用类候选保留但标注「请人工确认」。
- 置信度低于 `FP_AI_MIN_CONFIDENCE`（默认 0.55）或判定为「不是问题」的候选不会展示。

## 4. 工程限制

- 存储使用 SQLite（本机无 PostgreSQL）。SQL 集中在 `src/db/sqlite.ts` 与 `src/db/repository.ts`，
  可替换为 Postgres；并发写入能力弱于 Postgres，单实例部署即可满足 V0。
- 队列为进程内队列 + 数据库轮询，未使用独立消息队列；多实例 Worker 依赖数据库抢占，
  高并发下可能出现重复领取的极小概率（页面写入有唯一约束，不会重复创建）。
- 未实现验证码 / 风险验证，V0 仅用 IP 哈希限流、域名冷却与全局每日预算防滥用。
- 前端无构建步骤，使用原生 JS；未做国际化与移动端深度适配（已做基本响应式）。

## 5. 明确不开发（方案第 22 节）

登录注册、账户、团队权限、保存多个网站、定时扫描、邮件通知、支付套餐、CMS 接入、
自动修改网站、自定义复杂规则、历史趋势、企业 IM 集成、PDF 报告、白标、移动 App、
大型网站支持、全站 SEO / 性能 / 无障碍 / 安全审计。
